# 인물대백과사 운영 수첩

## 0. 서비스 오픈 전에 채울 것 (약관·방침의 노란 칸)
이용약관(`terms/index.html`)과 개인정보 처리방침(`privacy/index.html`)에 노란색으로 표시된 빈칸이에요. 오픈 전에 한 번에 채우고, 노란 표시(`class="fill"`)를 지워요.
- [ ] 시행일 (약관·방침 둘 다, 같은 날로)
- [ ] 운영자(대표) 이름 · 사업자 정보(사업자 등록을 했다면 등록번호·주소)
- [ ] 문의·신고용 이메일 (개인 메일과 분리 추천) — 약관 「운영자 정보」, 방침 11번
- [ ] 개인정보 보호책임자 이름·직책
- [ ] 백업 보관 기간(Supabase 요금제에 따라: 무료=자동 백업 없음, Pro=7일) — 약관 제16조, 방침 3번
- [ ] 서버 보안 기록 보관 기간(Supabase 요금제별 로그 보관 기간 확인) — 방침 3번
- [ ] 화면 제공 업체가 바뀌면(GitHub Pages → 다른 곳) 방침 5번 표 고치기
- [ ] 법률 전문가 검토 1회
- [ ] 약관·방침을 바꾸면 `editor/index.html`의 `TERMS_VERSION`도 올리기(동의 기록용)

## 1. 매일 점검 (5분)
1. 서가·내 서재·스튜디오가 열리는지(각 주소 한 번씩)
2. 관리자 페이지 「처리할 신고」 0건인지 — 있으면 당일 처리
3. 새 회원·새 책 수가 평소와 비슷한지(갑자기 폭증 = 스팸·공격 의심)
4. Supabase 대시보드: 저장 용량·전송량(Bandwidth)·DB 크기가 한도의 80% 미만인지
5. Supabase 로그: 로그인 실패·오류가 갑자기 늘지 않았는지
6. 서가에 새로 공개된 책 제목을 훑어보기(부적절한 내용)
7. 가입 확인 메일이 정상 발송되는지(주 1회 테스트 계정으로)

## 2. 매주
- 백업 파일이 실제로 만들어졌는지 확인(날짜·크기)
- Supabase 보안 권고(Advisors) 새 항목 확인
- 휴지통에서 30일 지난 책 정리 여부 결정

## 3. 매월
- 백업 복원 연습(테스트 프로젝트에 되살려 보기) — 복원해 본 백업만 믿는다
- 비용 확인(Supabase·도메인·GitHub)
- 관리자 계정 목록·비밀번호·2단계 인증 점검
- 외부 부품(THIRD_PARTY_NOTICES.md) 보안 공지 확인
