## 3. 제가 의심하는 곳(약한 순서)

### ① 글 흐름 엔진: 긴 글이 여러 쪽으로 저절로 이어지는 기능
가장 복잡하고 가장 많이 고친 곳이에요.
- **연결 방식**: 쪽마다 「나는 어느 쪽에서 이어졌다」(`flowFrom`)를 들고 있고, **바로 앞 쪽일 때만** 이어져요. 쪽을 옮기거나 끼워 넣거나 복제하면 연결이 끊기는데, 예전 연결 표시는 남아 있다가 다시 나란해지면 다시 붙어요. 이 「보이지 않는 상태」 때문에 같은 동작이 다르게 보일 수 있어요.
- **의심 시나리오**:
  - 이어진 원고 중간에 새 쪽 끼우기 → 앞 쪽에 글을 더 쓰기 → 끼운 쪽 지우기 → 원고 순서·중복·유실 확인
  - 한 문단이 한 쪽보다 긴 경우
  - 쪽 경계에 걸친 굵게·색 글자
  - 쪽 경계에서 Backspace·Delete를 아주 빨리 연타
  - 붙여넣기 → 되돌리기 → 다시 하기를 여러 쪽에 걸쳐 반복
- **실제 한글 입력기**(윈도우 MS 입력기, 맥 한글, 휴대폰)로 쪽 끝에서 받침 있는 글자를 치기. 자동 시험은 조합을 흉내만 냈어요.
- 알려진 동작: 쪽 맨 끝의 빈 줄(문단 사이 빈 줄)은 쪽 아래로 살짝 넘쳐 숨어 있을 수 있어요(글자는 아님).

### ② 저장
- **두 탭이나 두 기기에서 같은 책을 고치면 나중에 저장한 쪽이 이겨요**(충돌 처리 없음, 일부러 미룸). 원고 유실이 어떻게 보이는지 확인해 주세요.
- 저장은 「쪽 올리기 → 없어진 쪽 지우기」 두 단계라 한 번에 처리되지 않아요. 그 사이 인터넷이 끊기면 어떻게 되는지 봐 주세요.
- 인터넷이 오래 끊긴 채 계속 쓰기, 로그인이 만료된 채 쓰기

### ③ 체험 원고 임시 보관(어제 새로 만듦)
- 로그인 없이 쓴 책을 **그 기기의 브라우저(IndexedDB)**에만 남겨요.
- **공용 컴퓨터에서 다음 사람이 「이어 쓰기」로 앞 사람 원고를 볼 수 있어요.** 이게 받아들일 만한지, 안내가 충분한지 봐 주세요.
- 큰 영상을 여러 개 넣어 브라우저 저장 한도를 넘기면? 저장 실패가 화면에 제대로 드러나지 않을 수 있어요.
- 「내 서재로 옮기기」: 견본 책의 작가 미디어는 빼고 빈 자리로 둬요. 직접 넣은 미디어는 올려요. 올리기가 중간에 실패하면? 다른 기기·다른 계정에서는?

### ④ 저작권 보호(서가·비밀 링크)
- 복사·인쇄·내려받기·오른쪽 클릭 막기는 **화면(브라우저) 쪽 장치**예요. 개발자 도구나 화면 캡처는 막을 수 없어요(알려진 한계). 그 밖의 뚫리는 길을 찾아 주세요.
- 미디어는 **서명 주소**로만 줘요(공개 책 1시간, 내 책 최대 7일). 주소를 복사해 다른 곳에서 열 수 있는 시간이 받아들일 만한지 봐 주세요.
- **인쇄용 원본(2700px)**은 책 주인에게만 줘야 해요(서버 `media` 함수 `variant:'print'`). 남의 공개 책·비밀 링크·로그아웃 상태에서 받아지는지 시험해 주세요.
- 인쇄용 QR에는 비밀 링크 주소가 들어가요. 종이를 받은 사람은 누구나 열 수 있어요(설계상). 안내가 충분한가요?

### ⑤ 출력(화면용·인쇄용 전자책)
- 화면용 전자책에는 영상·노래를 크기와 상관없이 **모두 파일 안에** 담아요. 그래서 영상이 많은 책(최대 200MB)이면 파일이 커요. 휴대폰에서 열리는지, 만드는 중에 브라우저가 멈추는지 봐 주세요.
- PDF 버튼은 아직 없어요. 지금은 인쇄용 HTML → Ctrl+P로 만들어요. 쪽 나뉨이 편집기와 같은지 확인해 주세요.

### ⑥ 시험하지 못한 환경
- 자동 시험은 **가짜 서버 + 헤드리스 크롬(리눅스)**에서만 돌렸어요.
  - 실제 Supabase·Cloudflare R2와는 다를 수 있어요.
  - 시험용 크롬은 MP4(H.264)를 못 열어 영상 시험은 WebM으로만 했어요.
- 한 번도 확인하지 않은 환경: **사파리·아이폰·안드로이드 휴대폰 편집, 터치, 화면 읽기 프로그램(실제), 아주 큰 책(쪽 100개 이상), 느린 컴퓨터**
- 옛 「장(章)」 편집기(`editor/`의 예전 형식 책)는 최근 수정 범위 밖이에요(깨진 파일 거르기 등이 안 들어감).
