# 1 F07 팝업에서 뒤의 글상자가 삭제됨

**직접 재현 | P1 | 범위: 내려받기 선택 팝업 + Delete**

1. 체험 책의 글상자에 고유 문장을 입력하고 Escape로 글 편집을 끝냅니다. 상자는 선택된 상태로 둡니다. 재현용 예시 문장은 「팝업 뒤 원고 보존 검사」입니다.

2. 상단 「내려받기」를 누릅니다. 「화면용 전자책」 버튼에 포커스가 놓인 상태에서 Delete를 한 번 누릅니다. 파일 형식을 선택하거나 다운로드하지 않습니다.

3. 팝업이 열린 상태인지와 뒤의 원고를 확인합니다. 팝업을 닫고 툴바의 되돌리기를 눌러 복원도 확인합니다.

**실제 결과** 팝업은 계속 열려 있었지만, 선택했던 설명 글상자가 삭제됐습니다. 해당 문장의 DOM 개수는 1에서 0으로 바뀌었습니다. 팝업을 닫은 뒤 툴바 되돌리기 1회로 복원됐습니다.

**기대·수정 방향** 팝업 안의 키 입력은 팝업 범위에서 처리해야 합니다. 최상위 단축키는 활성 팝업과 실제 포커스 범위를 먼저 확인하고, 배경 문서의 삭제·이동 명령을 중단하십시오. 닫을 때 이전 포커스를 복원하십시오.

**완료 기준** 내려받기 팝업에서 Delete/Backspace/방향키/Undo를 사용해도 배경 문서 내용·위치가 바뀌지 않아야 합니다. 다른 팝업도 같은 기준으로 검사하십시오. 이번에 직접 재현한 키는 내려받기 팝업의 Delete입니다.

코드 위치: endEdit 210~216, delEl 228~230, 전역 keydown 602~610, openExport 628~633. 편집 종료가 선택 해제를 뜻하지 않으며, 버튼 포커스는 입력 필드 보호 조건에 포함되지 않습니다.

# 2 F05 페이지 선택 대상이 달라짐

**직접 재현 | P2 | 범위: 「n쪽 고르기」 명시적 선택 버튼**

1. 5쪽짜리 새 체험 책에서 3쪽을 엽니다. 여러 쪽 선택은 없는 상태로 시작합니다.

2. Ctrl·Shift 없이 「3쪽 고르기」를 한 번 누릅니다. 선택 상태가 바뀌는지 확인합니다.

3. 선택이 없는 상태에서 「2쪽 고르기」만 한 번 누릅니다. 선택된 페이지 ID와 개수를 확인합니다. 실제 삭제를 실행할 필요는 없습니다.

**실제 결과** 첫 시험에서는 3쪽의 aria-pressed가 false로 남았습니다. 둘째 시험에서는 누른 2쪽뿐 아니라 현재 3쪽도 true가 됐고, 패널에 「2쪽 선택」이 표시됐습니다. 「선택 해제」 후 둘째 시험을 반복해도 같았습니다.

**영향** 사용자가 고른 것과 일괄 배경 변경·삭제 대상이 달라질 수 있습니다. 실제 일괄 삭제까지 실행하지는 않았습니다. 삭제 전 확인창이 없는 것으로 해석하면 안 됩니다.

**수정 방향·완료 기준** 명시적 체크 버튼과 Ctrl/Meta+클릭의 선택 정책을 분리하십시오. 현재 쪽·다른 쪽 각각에서 첫 클릭은 해당 ID만 추가하고 두 번째 클릭은 그 ID만 해제해야 합니다. 키보드로 버튼을 활성화해도 동일해야 합니다.

코드 위치: 선택 버튼 117, 선택 처리 531~540. 선택이 비었을 때 현재 페이지를 먼저 추가한 뒤 누른 페이지를 다시 토글하는 537~538의 순서를 확인하십시오.

# 3 F06 설명 글상자가 완전히 겹침

**직접 재현 | P2 | 범위: 같은 이미지의 「설명 글 넣기」 반복**

1. 3쪽 「기억하고 싶은 순간」의 사진 자리에 portrait-test.png를 넣습니다.

2. 이미지가 선택된 상태에서 「설명 글 넣기」를 눌러 「첫 번째 설명글 - 원본」을 입력하고 Escape로 끝냅니다.

3. 이미지를 다시 선택해 「설명 글 넣기」를 누르고 두 번째 설명을 입력합니다. 두 설명의 위치와 미리보기를 비교합니다.

**실제 결과** 두 글상자의 위치·크기가 모두 left 10.526%, top 71.111%, width 78.947%, height 8.740%로 같았습니다. 기존 템플릿 설명 자리와도 겹쳤고, 미리보기에도 두 설명이 함께 남았습니다.

**영향** 설명이 없어졌거나 글자가 깨진 것처럼 보일 수 있고, 겹친 아래 상자를 선택하기 어렵습니다. 여러 설명을 허용하더라도 새 상자를 같은 좌표에 배치해서는 안 됩니다.

**수정 방향·완료 기준** 미디어와 설명의 연결을 관리해 반복 클릭 시 기존 설명을 편집하거나, 새 설명은 충돌 없는 위치에 놓으십시오. 템플릿 설명이 있는 경우 먼저 활용하고, 아래 공간이 부족하면 배치 선택을 제공하십시오. 반복 추가·기존 설명·페이지 하단 사례에서 중첩이 없어야 합니다.

코드 위치: 미디어 패널 169~171, addCaption 300~303. 기존 설명 및 주변 상자를 검사하지 않고 같은 y 위치에 새 상자를 추가합니다.

# 4 F08 체험본의 인쇄 QR이 음악을 가리키지 않음

**실제 출력물 검증 | P2 | 범위: 빈 체험 책에 직접 넣은 음악**

1. 새 체험 책 5쪽의 「눌러서 노래 넣기」로 tone-test.wav를 넣습니다. 합성된 1초 시험 음원입니다.

2. 「내려받기」 안내를 읽고 「인쇄용 전자책」을 내려받습니다. 이번 화면에는 체험 미디어의 QR 제한 안내가 없었습니다.

3. 생성 HTML의 음악 QR을 해독해 실제 주소를 확인합니다.

**실제 결과** 내려받은 HTML에 QR 1개가 있고, 해독한 값은 **https://archive4everyone.com/shelf/**입니다. 해당 음악의 식별자나 재생 대상이 포함되지 않았습니다. 출력 안내는 휴대폰으로 찍으면 노래가 재생된다고 설명합니다.

QR은 실제 SVG의 셀에서 주소를 해독했고 형식 정보 두 복사본과 오류 검증값이 일치했습니다. 예상 URL을 검증기에 입력하지 않았습니다. 휴대폰으로 직접 스캔하거나 도착 페이지를 연 검사는 아닙니다.

**수정 방향·완료 기준** 재생 대상이 없는 체험 미디어에는 유효한 재생 QR처럼 표시하지 마십시오. 계정 저장 후 발행·비밀 링크가 필요한 조건을 인쇄 전에 안내하고, 유효한 대상만 QR로 출력하십시오. 체험·미발행·공개·비밀 링크 상태를 각각 검증해야 합니다.

코드 위치: mediaLink 65~68, qrBlock 70~73, openExport 627~633. BOOK이 없을 때 공통 서가 주소를 반환하는 분기와 안내 조건을 확인하십시오.

![E08 음악을 직접 넣은 체험 책의 내려받기 안내: QR 제한 문구 없음](moa-audit-2-evidence/E08-print-no-warning.png)

# 5 F09 큰 투명 PNG가 흰 배경으로 바뀜

**직접 재현·대조 검사 | P2 | 범위: 1920px를 넘는 투명 PNG**

2. 1200px 파일을 사진 자리에 넣고 투명 영역을 확인합니다. 되돌리기로 사진 삽입을 취소합니다.

3. 같은 자리에 2200px 파일을 넣고 배경·파일 형식·해상도를 비교합니다.

코드 위치: shrinkImage 240~250, 처리 안내 258. 캔버스를 흰색으로 채운 뒤 JPEG로 변환합니다. 실제 서버 저장·인쇄 결과까지 모두 검사한 것은 아닙니다.

# 6 F10 손상된 이미지를 성공으로 처리

**직접 재현 | P2 | 범위: PNG로 선택되지만 디코딩되지 않는 파일**

1. invalid-image.png를 준비합니다. 이 시험 파일에는 이미지 데이터 대신 「MOA TEST: invalid image payload」라는 짧은 텍스트만 들어 있습니다.

2. 새 체험 책의 사진 자리에 이 파일을 선택합니다. 파일 선택기의 형식 필터를 통과한 뒤 실제 이미지가 읽히는지 확인합니다.

3. 성공·오류 안내와 생성된 이미지 상자를 확인합니다. 되돌리기로 시험 삽입을 취소합니다.

**실제 결과** 「사진을 넣었어요」라는 성공 메시지와 이미지 상자가 만들어졌습니다. 이미지의 complete는 true이지만 naturalWidth와 naturalHeight는 모두 0이었습니다. 선택한 파일이 실제 이미지로 디코딩되지 않았는데도 성공 처리됐습니다.

**수정 방향·완료 기준** 확장자·MIME 검사와 실제 디코딩 성공을 구분하십시오. 디코딩 실패 시 상자 교체·추가를 중단하고 기존 자리를 보존하며, 원인과 재선택 방법을 안내해야 합니다. 완료 이벤트나 complete만으로 성공 판정하지 마십시오.

실제 재현 범위는 손상 PNG입니다. 손상 JPEG·지원하지 않는 이미지·손상 영상·음악도 회귀 검사에 넣되, 이번에 모두 실패했다고 단정하지 않습니다.

코드 위치: shrinkImage 243의 catch 후 원본 반환, fillSlot 271의 im.onerror에서도 put 실행, addMediaPage 297의 im.onerror에서도 상자 추가. 영상 videoSeconds 252~257의 오류→0초 경로도 별도 검사하십시오.

# 7 F11 페이지 활성화 뒤 키보드 탐색이 끊김

**직접 재현·대조 검사 | P2 | 범위: 썸네일 Enter·Space와 이어지는 방향키**

1. 다중 선택이 없는 상태에서 2쪽 썸네일 자체에 포커스를 둡니다. 내부의 고르기·복제·삭제 버튼과 구분합니다.

2. Enter로 2쪽을 연 뒤, 마우스로 다시 누르거나 Tab을 누르지 않고 ArrowDown을 누릅니다.

3. 대조 검사에서는 2쪽 썸네일에 포커스를 두고 바로 ArrowDown을 누른 뒤 다시 ArrowDown을 누릅니다. 별도로 Space 활성화 뒤 포커스도 확인합니다.

| 검사 | 실제 결과 |
| --- | --- |
| Enter → ArrowDown | 활성 요소가 BODY로 바뀜. 이어진 Down 뒤에도 2 / 5 페이지 유지 |
| ArrowDown → ArrowDown | 첫 이동 후 3쪽 썸네일에 포커스 유지. 다음 키로 4 / 5 페이지 이동 |
| Space 활성화 | 활성 요소가 BODY로 바뀜. Space 뒤 Down 동작은 별도 반복하지 않음 |

**수정 방향·완료 기준** 썸네일을 다시 그린 뒤 안정된 페이지 ID로 포커스를 복구하십시오. Enter·Space·방향키 활성화의 도착 규칙을 일관되게 만들고 포커스를 화면에 표시해야 합니다. Enter/Space 뒤 연속 방향키로 페이지를 탐색할 수 있어야 합니다.

코드 위치: 썸네일 115, goPage 232, keydown 543~547. Enter/Space는 goPage 후 포커스 복원이 없지만, 방향키 분기에는 새 썸네일에 focus하는 코드가 있습니다.

## 별도로 확인한 정상 동작

• F07에서 삭제된 진단용 설명 상자는 팝업을 닫고 툴바 되돌리기 1회로 복원됐습니다. 모든 실행 취소가 고장났다는 뜻은 아닙니다.

• 작은 투명 PNG는 투명도를 유지했고, 일반 세로 PNG는 사진 자리에 비율을 지켜 들어갔습니다.

• 1초 WAV의 미리보기에서 재생 버튼이 일시정지 표시로 바뀌고 「0:00 / 0:01」이 나타났다가 재생 버튼으로 돌아왔습니다. 청감·기기별 음질 평가는 하지 않았습니다.

# 8 추가 검증 후보 - 확정 결함과 구분

아래 다섯 항목은 공개 소스에서 확인한 경로에 근거합니다. UI나 실패 조건을 충분히 시험하지 않았으므로 신규 확정 결함 7건에 포함하지 않았습니다. 1차 R01~R06도 계속 미완료 검증 항목으로 유지합니다.

## R07 세로·정방형 영상의 기본 잘림

영상은 원본 비율 대신 16:9 상자로 배치되고, 출력 CSS가 object-fit:cover입니다. 9:16·1:1·16:9 표식 영상을 편집·미리보기·HTML에서 비교하십시오. 전체 보기/영역 채우기를 선택하게 하고 기본 삽입에서 주요 내용이 잘리지 않는지 확인해야 합니다. 실제 세로 영상은 이번에 넣지 않았습니다. [272, 298, 640]

## R08 내보내기 실패를 성공으로 안내할 위험

뷰어 JS fetch 실패를 콘솔에만 남기고 빈 lib로 파일 생성이 계속되며 HTTP 성공 여부도 확인하지 않습니다. 미디어 포함 요청 실패도 조용히 넘길 경로가 있습니다. 개발 환경에서 뷰어 404·통신 실패·미디어 일부 실패를 만들어, 빈 책이나 불완전한 파일을 성공으로 안내하지 않는지 검사하십시오. [622~625, 641~655]

## R09 업로드 완료 시 삽입 대상이 달라질 위험

pendingSlot을 비동기 처리 후 읽고, 일반 삽입은 완료 시점의 현재 페이지를 사용합니다. A쪽에서 업로드 후 B쪽 이동, 두 파일의 완료 순서 역전을 개발 환경에서 검사하십시오. 요청마다 페이지·슬롯 ID를 고정하고 대상이 사라지면 명시적으로 처리해야 합니다. 실제 오배치는 미재현입니다. [237~277]

## R10 제목만 수정한 책의 재발행 감지

발행 스냅샷에는 제목을 저장하지만 pubDirty는 pages만 비교합니다. 별도 시험 계정에서 제목만 바꾸고 공개·비밀 링크 발행본 갱신을 검사하십시오. 실제 발행 payload의 변경이 상태 표시와 갱신 판단에 모두 반영되어야 합니다. 독자 화면의 불일치는 미검증입니다. [592, 772~786, 796, 815~820]

## R11 기존 글상자의 키보드 편집 진입

초기 글상자는 포커스 경로가 없고 포인터 조작 후 contentEditable이 됩니다. 키보드만으로 기존 제목·본문·설명을 찾아 편집을 시작하고 종료하는 전체 흐름을 검사하십시오. 새 글상자 생성 직후 입력되는 동작만으로 합격 판정하지 마십시오. [77~84, 199~208, 308~350]
