# 수정 요청서 2차 회신 — F05(P2) 「n쪽 고르기」 선택 대상이 달라짐

회신일 2026-10-19 · 대상 `studio/index.html` · 브랜치 `claude/confident-lovelace-w2mnqp`

## F05 페이지 선택 버튼이 누른 대상과 다르게 동작

- **상태**: 재현됨 → 수정. 수정 전 코드로 새 시험을 돌리면 11개 항목이 실패하고 중간에 멈췄습니다.
- **원인**: ✓ 버튼과 Ctrl+클릭이 같은 처리를 썼습니다. 선택이 비어 있으면 「보고 있는 쪽」을 먼저 넣고, 그다음 누른 쪽을 뒤집었습니다.
  - 3쪽을 보면서 「3쪽 고르기」 → 3쪽을 넣었다가 바로 뺌 → 아무 변화 없음
  - 3쪽을 보면서 「2쪽 고르기」 → 3쪽 + 2쪽 → 2쪽 선택
- **변경 내용**:
  - **✓ 버튼(「n쪽 고르기」)**: 누른 쪽만 넣고, 다시 누르면 그 쪽만 뺍니다. 보고 있는 쪽과 상관없습니다. 키보드(Enter·Space)로 눌러도 같고, 누른 뒤 포커스가 그 ✓ 버튼에 남습니다.
  - **Ctrl(맥은 ⌘)+클릭**: 파일 탐색기처럼, 선택이 비어 있을 때 처음 누르면 보고 있던 쪽도 함께 고릅니다(그 쪽이 이미 「지금 쪽」으로 표시되어 있으므로). 보고 있던 쪽을 Ctrl+클릭하면 그 쪽만 골라집니다(전에는 바로 풀렸음). 그다음부터는 누른 쪽만 넣고 뺍니다.
  - **1쪽만 골랐을 때**: 전에는 한 쪽만 고르면 오른쪽 패널이 「보고 있는 쪽」 기준이라, 2쪽을 고르고 배경을 바꾸면 3쪽이 바뀌었습니다. 이제 한 쪽이라도 고르면 패널이 「n쪽 선택」으로 바뀌고 배경·삭제는 고른 쪽에만 적용됩니다.
- **T19 결과**: 통과. 3쪽에서 「3쪽 고르기」 1회 → 3쪽만 선택(aria-pressed=true, 패널 「1쪽 선택」), 2회 → 해제.
- **T20 결과**: 통과.
  - 3쪽에서 「2쪽 고르기」만 → 2쪽만 선택, 보던 3쪽은 그대로. 「선택 해제」 뒤 반복해도 같음. 2회 → 해제
  - 2쪽만 고르고 배경 → 2쪽에만 적용
  - 키보드 Enter·Space로 같은 결과, 포커스 유지
  - 키보드로 2·4쪽 고른 뒤 「2쪽 삭제」 → 정확히 2·4쪽만 삭제(삭제 전 확인창 있음), Ctrl+Z로 복구
