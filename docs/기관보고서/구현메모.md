# 기관 보고서: 관리자 화면 구현 메모

> 나중에 이 보고서를 관리자 화면(`admin/`)에 만들 사람이 먼저 읽는 글이에요. (2026-11-20 작성)
> 대표가 정한 것은 `docs/결정기록.md` 6번·7번에, 아직 정하지 않은 것은 8번에 있어요. 이 글의 「추천」은 개발 Claude의 의견이고 정해진 것이 아니에요.
> 기관 이름, 가격, 실제 설문 응답은 이 저장소에 올리지 않아요.

## 1. 지금 상태

- **있는 것:** 기준 화면 `docs/기관보고서/기준화면.html`. 대표가 2026-11-20에 「고칠 것 없음」으로 확정했어요.
- **기준 화면의 한계:** 숫자와 한마디가 모두 견본이에요. 모아 DB와 연결되어 있지 않고, 파일 안 `COURSES` 묶음을 손으로 바꾸면 화면이 다시 그려져요.
- **없는 것:** 관리자 화면의 보고서 탭, 반(강좌) 구분, 설문 응답을 읽는 기능, PDF 저장.
- **건드리지 않은 것:** 서비스 화면, 서버 함수, DB. 기준 화면은 `docs` 폴더라 사이트 주소로 열리지 않아요.
- **기획 문서:** 대표의 Claude 문서 「모아 기관 보고서 PRD v0.1」(비공개).

## 2. 무엇을 만드는가

기관 담당자가 강좌 결과를 책임자에게 보고할 때 쓰는 자료예요. 대표가 관리자 화면에서 강좌를 고르면 보고서 화면이 뜨고, PDF로 저장해 기관에 보내요.

- 기관 담당자가 모아에 들어오는 화면이 **아니에요.** 기관 계정은 만들지 않아요(결정기록 6번).
- 모든 기관 강좌에 같은 양식을 써요.
- 핵심은 수강생이 모아를 쓰기 전과 후에 달라진 값을 그림으로 보여 주는 것이에요.
- 보고서 만들기는 「AI 안 씀」이에요.

## 3. 화면의 칸과 숫자가 오는 곳

| 칸 | 보여 주는 것 | 견본 묶음의 키 | 실제 자료가 오는 곳 | 구현할 때 필요한 것 |
|---|---|---|---|---|
| 강좌 정보 | 강좌 이름, 기관, 기간, 횟수, 참여 인원 | `name` `org` `period` `sessions` `people` | 대표가 입력 | 반 구분(4번) |
| 한 일 숫자 | 쓴 글 수, 완성한 책 수 | `posts` `books` | 모아 DB | 「쓴 글」「완성한 책」의 뜻을 정해야 함(아래) |
| 달라진 값 | 네 영역의 전·후 평균, 오른·같은·내린 사람 수 | `areas[]` `paired` | 구글폼 전·후 설문 | 응답 읽기(5번), 계산 규칙(6번) |
| 만족도 | 우리 질문 3개, 기관 자체 조사 결과 | `sat` | 마지막 수업 설문, 기관이 준 값 | 기관 값은 대표가 손으로 입력. 없으면 칸을 뺌 |
| AI와 쓰기 진행 | 단계마다 거기까지 가 본 수강생 수 | `steps[]` | `ai_threads.state.step` | 반 구분(4번) |
| 수강생 한마디 | 동의받은 한마디 | `quotes[]` | 마지막 수업 설문 | 동의 칸을 함께 받아야 함 |

**「쓴 글」「완성한 책」의 뜻(미정, 후보만):**
- 쓴 글: `ai_threads`에서 단계가 「담기」까지 간 글감 수. 다만 AI 없이 쓴 글은 빠져요. 쪽 수(`pages`)로 세는 방법도 있어요.
- 완성한 책: `books.published_at`이 있는 책(발행함). 서가 공개(`is_public`)와는 달라요. 수업에서 「완성」을 무엇으로 보는지 대표께 물어요.

## 4. 반(강좌) 구분

지금 DB에는 회원이 어느 기관·어느 반인지 적는 곳이 없어요. 보고서를 자동으로 만들려면 이것이 먼저예요.

추천하는 모양이에요.

- `courses`: 강좌 한 줄(이름, 기관 표시 이름, 시작일, 종료일, 횟수)
- `course_members`: 강좌와 회원을 잇는 줄(`course_id`, `user_id`)
- 두 표 모두 관리자만 읽고 쓰게 해요(`admin_users` 기준 RLS, 기존 `admin_usage`와 같은 방식).
- 기관 이름은 DB에만 두고 저장소에는 적지 않아요.

관리자 화면 「회원」 탭에서 회원을 강좌에 넣는 단추가 필요해요.

## 5. 설문 응답을 읽는 방법

두 가지 길이 있어요. 대표가 정하지 않았어요.

| 길 | 방법 | 좋은 점 | 아쉬운 점 |
|---|---|---|---|
| 가 (추천) | 구글폼 응답 파일(CSV)을 관리자 화면에 올리면 브라우저 안에서만 계산하고 저장하지 않음 | 모아가 설문 응답을 보관하지 않아 개인정보 부담이 작음. DB 변경 없음 | 보고서를 다시 볼 때마다 파일을 다시 올려야 함 |
| 나 | 응답을 모아 DB에 저장 | 언제든 다시 볼 수 있고 강좌끼리 비교 가능 | 개인정보 처리방침 개정이 필요하고, 보관·삭제 규칙을 정해야 함 |

어느 길이든 같은 사람의 전·후를 이어야 해요. 이름 대신 수강생 번호를 쓰는 쪽을 추천해요(미정).

## 6. 계산 규칙 (기준 화면이 따르는 규칙)

- 질문은 영역마다 2문항, 답은 1~5점이에요. 한 사람의 영역 점수는 두 문항의 평균이에요.
- 전·후 설문에 **모두 답한 사람만** 비교에 넣어요. 그 인원(`paired`)을 화면에 적어요.
- 영역의 전·후 값은 그 사람들의 평균이고, 소수 첫째 자리까지 보여 줘요.
- 「오른 사람」은 영역 점수가 전보다 후에 높은 사람이에요. 같음과 내림도 따로 세요(마우스를 올리면 보임).
- 「가장 크게 오른 영역」은 후 평균에서 전 평균을 뺀 값이 가장 큰 영역이에요.
- 응답 인원이 아주 적을 때(5명 미만 추천)는 그림 대신 글로 적어요(미정).

## 7. 그림 규칙

- 전후 비교는 아령 모양 그림이에요. 1~5점 자 위에 전은 빈 고리, 후는 채운 점, 둘 사이를 선으로 이어요.
- 색은 초록 한 가지의 두 단계만 써요. 숫자와 글자는 본문 글자색이에요.
- 값은 점 옆에 직접 적어요. 낮은 값은 왼쪽, 높은 값은 오른쪽이에요.
- 색과 글꼴은 관리자 화면(`admin/index.html`의 `:root` 색 이름)과 같아요.

## 8. 관리자 화면에 옮기는 순서 (추천)

1. 대표께 8번 미정 항목을 묻고, 동작을 한 줄 규칙으로 합의해요.
2. 반 구분(4번)을 만들어요. DB 마이그레이션과 `tests/db` 확인이 필요해요.
3. `admin/index.html`의 탭(한눈에 보기 · 신고 · 책 · 회원) 옆에 「강좌 보고서」 탭을 더해요. 기준 화면의 `render(c)`가 받는 묶음 모양을 그대로 쓰면 그리는 부분은 옮기기만 하면 돼요.
4. 한 일 숫자와 진행 단계를 DB에서 읽어 묶음을 채워요.
5. 설문 응답 읽기(5번)를 붙여요.
6. PDF는 브라우저 인쇄와 인쇄용 CSS(A4, 2쪽 추천)로 만들어요.
7. `tests/e2e/admin-test.mjs`에 시험을 더하고, 판 번호를 바꿔요.

## 9. 지킬 것

- **시기:** 모바일 정식 버전까지는 새 기능을 더하지 않아요(결정기록 0번). 이 구현은 그 뒤예요.
- **과장하지 않기:** 「효과 입증」, 「통계적으로 유의미」라고 쓰지 않아요. 질문은 모아가 직접 만든 것이고 검증된 심리 검사가 아니라는 설명 줄을 화면 아래에 둬요. 내려간 영역도 그대로 실어요.
- **개인정보:** 개인별 점수는 싣지 않고 반 전체 값만 실어요(추천). 우울 같은 건강 정보는 묻지 않아요(추천). 처리방침과 실제 동작이 같아야 해요.
- **저작권:** 한마디는 본인이 동의한 것만 실어요(추천). 책 본문과 사진은 싣지 않아요.
- **견본 표시:** 견본 숫자로 화면을 보여 줄 때는 「견본 자료」 표시를 둬요.
